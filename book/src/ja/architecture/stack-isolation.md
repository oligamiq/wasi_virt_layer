# スタック分離とハンドオフ

WASI Virtual Layer (WVL) は、仮想ファイルシステム (VFS) とターゲットのWebAssemblyモジュール間、特にマルチスレッドや非同期環境においてスタックの衝突を防ぐための、堅牢なスタック分離とハンドオフ機構を提供します。

## Stack Handoff & Isolation ABI

スタック分離の核となる機能はライブラリ側 (`wasi_virt_layer`) で管理されています。ランタイムがターゲットモジュールのスタックと、スタンバイ状態のスタック（またはVFSスタック）を動的に切り替えることを可能にするABI (Application Binary Interface) を定義しています。

### 主要なコンポーネント

*   **`StackInfo`**: スタックのサイズ、現在のスタックベースポインタ、およびスロットインデックス（マルチメモリ環境用）を含む、スタックの設定とランタイム状態を表します。
*   **`StackHandoffRecord`**: シリアライズされたスタンバイスタックのハンドオフを管理します。アトミックロックとメモリポインタを使用して、スタックの切り替えを安全に行い、複数のインスタンスが相互作用する際のデータ破損や衝突を防ぎます。
*   **Ensure / Release 操作**: 
    *   `ensure_vfs_stack` や `ensure_wasm_stack` のような関数は、特定の実行コンテキストに移行する際に呼び出され、有効なスタックがインストールされていることを保証します。
    *   `release_vfs_stack` や `release_wasm_stack` のような関数は、ハンドオフを実行し、スタックをスタンバイ状態に戻します。

## Wasm Stream Passes (CLI 側の計装)

`wasi_virt_layer-cli` は、ビルドプロセス中に「ストリームパス (Stream Passes)」と呼ばれる一連の処理を通じてWebAssemblyバイナリに計装を行い、スタック分離を自動化します。

### シングルメモリターゲット
*   **`ExportStackPreVfsStreamPass`**: VFSモジュールにスタックを持たない動的スタックハンドオフラッパーをエクスポート関数に注入することで計装します。
*   **`ExportStackPreTargetStreamPass`**: 関数へのエントリ時と終了時にプライベートスタックを獲得・解放するように、シングルメモリのターゲットモジュールを計装します。

### マルチメモリターゲット
マルチメモリのシナリオでは、CLIはスタック管理に「アリーナ (Arena)」アプローチを使用します。

*   **`ExportStackArenaStreamPass`**: マルチメモリターゲットモジュール内に予約済みのスタックスロットアリーナを作成します。これは、残りのメモリ空間を仮想化するために、すべての線形メモリオペレーション（ロード、ストア、`MemorySize`、`MemoryGrow` など）にオフセットを適用します。
    *   アトミックCAS (Compare-And-Swap) 操作を使用してアリーナ内のスタックスロットをアトミックに要求するWebAssemblyヘルパー (`build_slot_acquire`) を生成します。
    *   また、アリーナビットマップ内のスロットをアトミックにクリアするヘルパー (`build_slot_release`) も生成します。
*   **`ExportStackMultiMemoryTargetStreamPass`**: アリーナのスロット獲得メカニズムを利用して、エクスポート関数を安全にラップするマルチメモリターゲット用のラッパー関数を発行します。
